// Escape diagnosis for SD-024. Kept with the task evidence so the next session can
// continue from the exact facts instead of repeating the probes.

Facts (2026-09-27):

1. The handler runs and takes the close branch.
   - A bubble-phase window listener observes `event.defaultPrevented === true` after a
     real Escape.
   - `Event.prototype.preventDefault` was patched during a press and the captured stack
     is `media/app/entry.js:2536`, which is exactly
     `case "closeInspector": event.preventDefault();`.
2. The reducer path is reached but produces no change.
   - The served bundle contains the reducer case
     (`media/app/state.ts` line ~430: `case 'inspectorClosed': return state.inspectorOpen ? { ...state, inspectorOpen: false } : state;`),
     and the bundle has it at line 2195.
   - A MutationObserver on `.sd-inspector` records **no class change at all** while the
     inspector is open, so `renderDetails` never ran with `inspectorOpen: false`.
   - Sampling `getState().inspectorOpen` every 10 ms across the press never shows false,
     so this is not a close-then-reopen.
   - Conclusion so far: the `dispatch` that runs sees `state.inspectorOpen === false`
     (so the reducer returns the same state), while `window.sharpdepsApp.getState()`
     reports true. The two reads disagree inside one synchronous handler.
3. This is independent of the event source.
   - A synthetic Escape dispatched on `window` closes the pane (verified earlier).
   - A synthetic Escape dispatched on the focused element (`g`, bubbling) does **not**
     close it, exactly like a real key. So `isTrusted` is irrelevant; the event path
     (bubbling from the SVG) is the difference.

Next step (smallest decisive probe): log the closure's own reads from inside the keydown
handler, e.g. temporarily expose `window.__inspect = () => state` next to the handler and
compare it with `window.sharpdepsApp.getState()` in the same turn. If they differ, look
for a second `createViewerApp` call or a duplicated listener (for example `entry.js`
evaluated twice), because the reducer and `getState` cannot otherwise disagree.

What is verified and unaffected: the Close button, mouse selection, keyboard selection,
`/` (search focus), `g`/`t` (view switch), Enter on an edge reaching evidence and
openEvidence, high contrast, reduced motion, and the three widths.
