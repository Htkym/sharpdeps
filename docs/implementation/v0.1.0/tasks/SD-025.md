## 実装内容

1. **精度golden**：型・関係・根拠・宣言・生成文書・循環の総数、変種ごとの型/関係数、basis・confidence・関係種別の分布、
   limitation、文書originの分布を固定した。id・時刻・順序に依存しない形にしてあり、`SHARPDEPTS_UPDATE_BASELINE=1`で
   更新、差分は最初の20件を失敗メッセージに出す。
2. **TFM差の明示**：Domainが**2変種**（net10.0 / netstandard2.0）として現れ、それぞれの型・関係数がgoldenに残る。
   「マルチTFMを1つに混ぜない」ことをテストで固定した。
3. **QuickとSemanticを意図的に別期待値**：Semanticは `basis === symbolResolved` かつ `confidence === resolved` のみで
   あることをassertする（Quickの宣言/推定とは別物）。
4. **失敗系**：未restoreプロジェクト（`semantic-unrestored`）とジェネレーター取得失敗の経路は既存の統合テストで
   自動化済み。SDKなし環境はこの環境では作れないため未検証として残す。
5. **発見と修正（精度バグ）**：goldenを作る過程で、マルチTFMプロジェクトの**2番目以降のTFMの型13件が、
   どのプロジェクト項目にも属さない変種IDを参照している**ことを検出した。原因はライターが論理プロジェクト
   単位で1件だけプロジェクトを出していたこと。論理IDにTFMを含めて**変種ごとに1件**出すよう修正し、
   「未知の変種を参照する型0件」を確認した。

## 未検証事項

- **SDKなし環境**：MSBuild/SDKが無い場合の失敗系は環境を作れず未実施（SD-028の環境検証で扱う）。
- **循環を含むfixture**：このfixtureは循環0件で、循環の精度はSD-012の単体テスト側で固定している。実プロジェクトの
  循環をgolden化するのはSD-027以降。
- **goldenの粒度**：ノード/辺の全リストは固定していない（idが実行ごとに安定しないため）。必要なら正規化した
  差分goldenを追加する。

## 判断・補足

- goldenは「id・時刻・順序に依存しない集計」にした。全リストを固定すると、無関係な変更で落ちて精度の退行が
  埋もれるため。
- マルチTFMの論理IDにTFMを含めたのは、プロジェクト項目のid重複を避けつつ「TFMを混ぜない」原則を守るため。
  単一TFMプロジェクトのidは従来どおりで、既存のgolden・分析IDへの影響は最小にした。
