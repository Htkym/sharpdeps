## 実装内容

1. **固定fixture**：`.local/perf/big`に40名前空間×10型（400ファイル）を決定的に生成し、
   前の名前空間へ2本・自名前空間へ1本の参照を持たせる（辺と循環を確実に発生させる）。
2. **計測**：`scripts/perf.js`がQuickを3回実行して中央値・最小・最大・出力サイズを、
   Semanticを実ベースラインで1回実行して時間・ピークワーキングセット・出力サイズを記録する。
   環境（CPU数・メモリ・プラットフォーム）も残す。
3. **後始末の検証と修正**：計測中に、コントローラが解析後に**実行ディレクトリを削除している**
   ことを発見した。ストアは根拠を**必要時に読む**設計なので、削除すると根拠ページングと
   エクスポートが壊れる。実行ディレクトリは**新しい2件を残して剪定**する方式に変更し、
   単体テストで「最新は残る・古いものは消える」を固定した（SD-014の期待値変更は理由付き）。
4. **残留確認**：計測前後でdotnetプロセスの数が変わらないこと、作業ディレクトリが残らないこと、
   フィクスチャに余計なファイルが残らないことをレポートに含める。

  単体テストで確認しているが、時間の実測はしていない。
- **大規模実ソリューション**：合成fixtureのみ。数千ファイルの実プロジェクトは未計測。
- **レイアウト・検索・選択の個別計測**：ブラウザ検証（SD-004/017）で体感確認のみ。
