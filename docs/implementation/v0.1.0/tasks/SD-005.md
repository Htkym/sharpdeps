## 実装内容

1. 単一ファイル解析器を Contracts / Core / Quick / QuickHost へ分割し、Semanticは既存の
   Roslyn / SemanticHost のまま維持した。
2. QuickからMSBuild系実装への参照を外した。Quickが参照するのは
   `Microsoft.CodeAnalysis.CSharp`（構文解析のみ）だけである。
3. Tarjan SCC、ソリューション発見（.sln/.slnx/単一プロジェクト）、プロジェクト種別判定を
   それぞれ独立したクラスへ移し、単体テストを付けた。
4. ビルドをfile-based appのpublishから明示的なcsproj publishへ変更した。
   出力は `analyzer/bin/quick/code-map.dll`（assembly名は互換のため `code-map` のまま）と
   `analyzer/bin/semantic/sharpdeps-semantic-host.dll`。
5. Extension側の `locateAnalyzer` を新レイアウト優先へ変更し、ソース実行フォールバックを削除した。
6. 依存境界の自動テストを追加した（QuickアセンブリがMSBuild/Workspacesを参照しないこと、
   publish物に `Microsoft.Build*.dll` が無いこと）。

## 未検証事項

- SDKを実際に持たない環境でのQuick起動（依存関係はMSBuild非参照を実測）。
- Linux / macOS での `dotnet build` / `dotnet test`（Windowsのみ実施）。
- VSIXをクリーンなExtension Hostへ入れての動作（SD-029）。
- `.slnx` のフォルダ名が `/src/` のまま表示される既存挙動（テストで固定）。SD-006で正規化する。
- 旧レイアウト `analyzer/bin/code-map.dll` は後方互換のため探索対象に残している。

## 判断・補足

- QuickのRoslynは v0.0.4 と同じ 4.14.0 に固定した。分割で解析結果が変わらないことを
  スナップショットで担保するためで、更新は別タスクで判断する。
- QuickHostの出力アセンブリ名は `code-map` を維持した（Extension側の探索とスナップショット
  テストを変えずに済む）。ファイル名の互換を保つ意図をcsprojにコメントしている。
- SemanticHostのpublishは `build:analyzer` に含めるが、VSIXへは同梱しない（SD-029で判断）。
- `.playwright-mcp/**`（Playwrightの作業ファイル）がVSIXに混入していたため除外を追加した。
