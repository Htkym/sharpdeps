## 実装内容

1. **Trust guard**：未信頼ワークスペースでは解析を起動しない（MSBuild評価とプロジェクトロジックの
   実行を伴うため）。理由を表示し「信頼を管理」を提示する。保存済み結果の表示・復元は
   データのみなので許可する。
2. **CSPの最小化**：`default-src 'none'`、スクリプトはnonceのみ（`unsafe-eval`なし）、
   `worker-src blob:`、`connect-src`はwebview自身のリソースのみ、`object-src`/`frame-src`/
   `base-uri`/`form-action`を`'none'`。CSP生成を`src/view/csp.ts`へ分離し、単体テストで固定した。
   パネルは`enableCommandUris: false`・`enableForms: false`を明示する。
3. **境界検証**：検索クエリに200文字の上限を追加（UIへ反響するため）。プロトコルは既存の
   IDパターン・cursor検証・未知typeの拒否に加えてこれを検証する。
4. **経路の封じ込め**：`isInsideRoot`で`..`脱出・絶対パス・不正なセグメントを拒否する。
   ルート外のファイル（linked file）を開くこと自体は正当なので許可しつつ、**内容ハッシュの比較では
   読まない**（任意ファイルの読み取りを避ける）。判断はログに残す。
5. **表示・出力の無害化**：`sanitizeSingleLine`で改行・制御文字を1行化し、Markdownの箇条書きや
   Mermaidラベルを壊せないようにする。Mermaidは引用符・バッククォートを無害化する。
   悪意ある型名（`<script>`・改行・バッククォート）をコンテキスト/JSON/Mermaidへ通すテストを追加。
6. **漏えい対策（既存の確認）**：絶対パスはレポートに出さない（SD-011/019でテスト済み）、
   ソース全文は含めない、snippetはopt-in、一時領域はglobalStorage配下、生成文書はread-only。

## 判断・補足

- CSPをvscode非依存のモジュールへ分離したのは、ポリシーを単体テストで固定するため。
  セキュリティ既定値は「意図して書かれている」ことが重要で、暗黙の既定に頼らない。
- ルート外のlinked fileは「正規の解析対象」と「任意ファイル読み取り」を区別するため、
  開くのは許可し、読み取り（ハッシュ照合）は行わない方針にした。
