## 実装内容

1. **バージョン**：製品版を0.1.0へ揃えた（lockfileも更新）。
2. **VSIX内容の検査**：`npm run check:vsix`がパッケージし、**必須**（拡張本体・webview entry・
   worker・CSS・QuickHostのDLLとruntimeconfig・README/CHANGELOG/notices）と**非同梱**（src/tests/
   schemas/docs/.local/node_modules/analyzerのソース、および`analyzer/bin/semantic/`）を検査する。
   検査結果は`docs/implementation/v0.1.0/evidence/sd-029-vsix.json`へ保存。
   実測：**46エントリ・約6.8MB**、必須はすべて存在、混入なし。
3. **Semanticホストの非同梱**：このバージョンの拡張はSemanticを起動しない（モード選択時は明示的に
   非対応を通知）ため、`analyzer/bin/semantic/`は**同梱しない**ことを検査で固定した。
4. **ドキュメント**：READMEに0.1.0の操作（選択→根拠→コード移動、エクスポート、状態復元、
   ショートカット）を追加し、以前のUIのスクリーンショットであることを明記した。CHANGELOGに
   0.1.0の変更点をまとめた。
5. **CI**：アナライザのビルド、VSIX内容検査、`@vscode/test-electron`を用いるE2E（現状は
   `continue-on-error`）を追加した。

## 未検証事項

- **VSIXを導入したクリーン環境での再検証**：`SHARPDEPTS_E2E_MODE=vsix`を実装したが、
  この環境ではCLIからの`--install-extension`（新規プロファイル）が完了せず中断した。
  依存拡張の導入時と同じ挙動で、環境要因と見ている。VSIX内容そのものは`check:vsix`で確認済み。
- **Semanticの実機動作**：このバージョンはSemanticを起動しないため対象外（SD-030の判定材料）。
- **READMEの画像差し替え**：新しいUIのスクリーンショットへの差し替えは未実施（画像は旧UIのまま
  である旨を明記した）。
- **ELKのライセンス全文同梱**：noticesに名称・ライセンス・入手先を記載したが、EPL-2.0の全文は
  npmパッケージ側に依存している。

## 判断・補足

- VSIX検査をスクリプト化したのは、`vsce ls`の目視確認では非同梱漏れ（テストやソースの混入）を
  見落とすため。CIでも同じ検査を回す。
- E2EをCIで`continue-on-error`にしたのは、VS Codeバイナリの取得と単一マシンでの実行が
  不安定なため。判定はSD-030で行う。
