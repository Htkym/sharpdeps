## 実装内容

1. **コマンド**：`sharpdeps.showTypeDependencies` / `sharpdeps.showTypeDependents` を追加。
   既存のコマンドID（showDependencyMap/refresh/copyMermaid/exportSvg/exportPng）は維持している。
2. **カーソル位置→型**：解析結果に永続化した**宣言位置索引**（`declarations.ndjson` +
   `declarationIndex`）を引き、その文書・そのオフセットに**宣言されている**型を返す。
   名前では一切照合しないため、同名の別プロジェクトの型へ結び付くことはない。
   1ファイルが複数プロジェクトに含まれる場合は、ファイルを包含するプロジェクトの宣言を選び、
   選んだプロジェクト名を出力チャネルとInspectorに示す。
3. **案内**：解析結果なし・Quickのみ（宣言位置を持たない）・ファイルが解析対象外・
   カーソル位置に型がない場合は、理由を表示して「解析する」を提示する（黙って何もしない）。
4. **openEvidence/openDeclaration**：Webviewは不透明IDのみを送り、ホストが
   `findEvidence`/`declarationsForType` で位置を解決して開く。
   - 生成文書は `sharpdeps-generated` のread-only providerで開く（リポジトリへ書かない）。
   - ユーザー文書は開く前に**内容ハッシュを照合**し、不一致なら「古い行へ移動する可能性がある」と
     警告して承諾を求める（黙って飛ばない）。
   - 未保存変更がある場合はその旨を警告する（位置は保存内容基準のため）。
   - 位置情報を持たない根拠（宣言のみ）は開かず、その旨を伝える。
5. **reveal**：ホスト→Webviewの`reveal`メッセージでエンティティとスコープを指示し、
   Webviewは新しいスコープの射影を要求して選択・Inspectorを開く。再解析は起動しない。

## 判断・補足

- 宣言位置は根拠と同じ「サイドファイル＋索引」方式にした。report-v2.jsonを肥大化させず、
  既存の検証・ストリーミングの仕組みをそのまま使えるため。
- 位置の照合は「内容ハッシュ」で行い、不一致時のみ確認する。ハッシュが照合できない場合
  （記録なし・読み取り不可）は移動を止めず、その限界はこのメモに残す。
- 型ID・変種IDはライターでv2 IDへ変換してから宣言レコードへ書く。索引の内部IDをそのまま
  出すと、スナップショットの型IDと一致しない（契約テストで検出して修正した）。
