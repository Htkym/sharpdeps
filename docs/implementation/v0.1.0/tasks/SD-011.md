## 実装内容（今回の範囲）

1. **証拠位置の保持**：宣言・実使用の根拠は、実ファイルの物理spanと0-based UTF-16の
   行/文字を保持する（SD-009/010で実装済み）。v2出力でそのまま検証できるようにした。
2. **sourceManifest**：シンボル索引が登録した文書（相対パス・SHA-256・サイズ・origin）を
   snapshotの`sourceManifest`へ出力する。`origin`は現時点で`userSource`のみ。
3. **外部型の材料化**：解決できない型（BCL・パッケージ）を`(external)`プロジェクト配下の
   外部型ノードとして出力し、辺が存在しないノードを指さないようにした。
   アセンブリ識別子は内部の同一性判定にのみ使い、表示名をノード名にする。
4. **v2契約の検証**：実SemanticHostの出力がruntime validator・JSON Schema・根拠スキーマを
   満たし、ReportStoreへ登録して根拠ページングが動くことを確認した。

## 判断・補足

- relationsは**型粒度のみ**出力し、名前空間/プロジェクト粒度はホスト側で関係の両端の
  親から集計する（根拠の二重出力を避けるため）。SD-017の射影で実装する。
- 外部型は1つの`(external)`プロジェクトにまとめる。アセンブリごとのプロジェクト分割は
  ノード数の増加に見合わないため行わない（アセンブリ識別子での区別は維持）。
- `memberCount`は索引のメンバー数から実値を入れる（nullは契約違反になるため）。
