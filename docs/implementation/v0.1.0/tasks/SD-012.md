## 実装内容

1. **集計**：根拠を `(basis, source, target)` でまとめ、`relations`（関係数＝一意な組）と
   `evidence`（箇所数）を別々に保持する。関係には kinds・参照元メンバー数・
   参照元文書数・生成コード根拠数・公開面根拠数・confidenceを含める。
2. **粒度**：`Type` / `Namespace` / `Project` を切り替えて集計する。親が同じ関係は
   その粒度の辺にしない（自己辺を作らない）。型粒度の自己参照は関係として残すが、
   循環としては扱わない。
3. **循環**：basisごとに分けてSCCを計算し、basisを混ぜた偽の循環を作らない。
   代表閉路（witness）は**そのSCC内に実在する辺だけ**をDFSで辿って求める。
   ノード名をソートして結んだものを経路にしない。全閉路列挙はしない。
4. **索引と探索**：forward/reverse adjacencyを索引化し、深さ1〜3のBFSで
   依存先/被依存元を返す。訪問済み集合により循環があっても停止する。
   表示予算（ノード上限）を超えた分は打ち切り件数として返す。
5. **射影**：表示予算による射影を解析結果とは別に作る。選択中・循環確認中などの
   優先IDを先に確保し、残りは次数の降順で選ぶ。総数と省略数、`truncated` を必ず返し、
   解析結果（SCCを含む）は変化させない。

- 閉路の複数候補列挙、最短閉路の選択は行わない（計画どおり代表1本）。

## 判断・補足

- 関係数の定義（一意な組）と箇所数（根拠件数）は `AnalysisGraph.RelationCount` /
  `OccurrenceCount` として分離した。`docs/analysis-semantics.md` の定義と一致する。
- witnessは「開始ノードへ戻る経路」を1本見つける方式にした。SCCは強連結なので
  必ず存在し、訪問済みパス集合で探索が有界になる。
- 表示予算の射影では、予算超過と分かった関係を結果に含めない（探索結果と
  ノード上限の整合を保つ）。
