## 実装内容

1. 計画書5章のモデルをJSON Schema 4ファイルへ落とし、TS型を写像した。
2. ID生成（`prj` / `var` / `ns` / `ty` / `mb` / `rel` / `ev` / `cyc` / `doc` / `dg` / `an`）を
   SHA-256先頭16桁で実装し、絶対パス・シンボル名をIDへ入れない。
   partialは宣言キーを統合、genericはdocumentation comment IDで正規化、
   外部型はAssemblyIdentityで区別する。
3. `validateSnapshot` / `validateEvidenceRecord` を実装し、構造・enum・ID書式・
   参照整合性（存在しないEntity ID、重複ID、未知のrelation参照）を拒否する。
4. `protocolVersion`・`requestId`・`analysisId`・`capabilities`・`partial` を
   プロトコルへ実装し、未知メッセージ型と不正IDを拒否する受信側検証を追加した。
5. v1レポートをv2へ写像するadapterを実装した。`confidence: inferred`、
   `capabilities.typeGraph: false`、`completeness: partial`、witnessなし、
   位置なしの文書レベル根拠、明示的な `limitations` を付ける。
6. ajvによる契約テストで、adapter出力・手書きsemantic fixture・goldenメッセージ・
   画面状態がschemaに適合することを確認した。

## 未検証事項・先送り

- Webview/パネルはまだv2プロトコルを使わない（現行v1のまま）。切り替えはSD-013/SD-015。
- 根拠NDJSONのbyte offset運用とページングはSD-013で実装・検証する。
- semantic fixtureは手書きであり、実アナライザー出力ではない（ADR 0002に明記）。
- 検証はWindowsのみ。Linux/macOSは未実施。

## 判断・補足

- 計画書のschema 3ファイルに加え、根拠1行を検証する `evidence-v2.schema.json` を追加した。
- `evidenceIndex` は `null` を許容する（メモリ上にしか根拠を持たない生産者のため）。
- `kinds` に宣言レベルの3種を追加した（宣言関係にも種別表示が必要なため）。
- 実行時検証は依存を増やさず自作validatorとし、ajvは契約テスト専用（devDependency）。
