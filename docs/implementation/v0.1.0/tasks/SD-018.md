## 実装内容

1. **Node Inspector**：粒度・種別・所属プロジェクト・循環・外部/生成の別、依存先/被依存の一覧
   （クリックで移動）、次数（出/入の箇所数と関係数）を表示する。
2. **Edge Inspector**：basisの説明（**Semantic（解決済み参照）** と **Quick（宣言/推定）** を明示）、
   kinds、箇所数、生成根拠数、public surface数、循環、関係IDを表示する。
   集約辺（名前空間・プロジェクト粒度）は下位の関係ごとの箇所数を一覧し、箇所数の合計と
   代表関係のページを区別して示す（「N件の関係を集約、合計M箇所、表示中は代表関係」）。
3. **根拠一覧**：種別、確信度（解決/推定）、生成、公開のバッジ、`path:line:character`（0-basedを
   1-basedへ変換）、`#line`によるmapped location、スニペット、コピー。
   レコードは防御的に読み、欠けたフィールドでも表示が壊れない。
4. **ページング**：`nextCursor`がある場合のみ「Load more evidence」を出し、明示操作でのみ次ページを
   要求する（再描画では読み足さない）。追加ページはIDで重複排除して連結する。
5. **不完全性の注記**：解析結果のlimitationのうち、根拠・生成に関係するものを詳細内に再掲する。
   Semantic以外のbasisには「宣言・推定であり実参照ではない」旨を明示する。
6. **再解析しない**：Inspectorはstoreへの問い合わせだけで構成し、`analyze`は一切送らない。

## 判断・補足

- 集約辺の箇所数と根拠totalの関係は、隠さずに両方を出す方針にした。型粒度では1対1で一致し、
  集約辺では「合計」と「代表関係のページ」を明示する。
- 根拠の`documentPath`はbridgeがmanifestから付与する。Webviewにmanifest全体を渡さず、
  表示に必要な相対パスだけを渡すため。
- 選択でInspectorを開くようにした（従来はデータ到着時のみ）。Inspectorの開閉は
  SD-017の検証どおりレイアウト・cameraに影響しない。
