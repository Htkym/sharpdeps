## 実装内容

1. **階層ツリー**：射影から `Project → Namespace → Type` を組み立て、子は展開時に
   初めて描画する。展開状態はコンポーネント側の集合で管理し、DOMから逆算しない。
   射影に含まれない子のホスト取得はSD-017のスコープ要求で接続する。
2. **全体検索**：検索はホストの全インデックス（`searchEntities`）へ問い合わせ、
   表示中の射影に無い型も結果に含める。結果は `visible` / `outsideBudget`（表示予算外）/
   `outsideFilters`（フィルター外）に分類し、バッジと「Show」で明示的に一時表示する。
   一時表示の解除ボタンも出す（復帰導線）。
3. **Table**：100件/ページ、列ヘッダでソート（同じ列で昇順/降順、別列で昇順に戻る）、
   行選択、Enter/ダブルクリックで詳細。並び順は名前→IDの順で決定し、
   同じ入力なら同じ順序・同じページ境界になる。
4. **フィルター**：同一カテゴリ内はOR、カテゴリ間はAND（`matchesFilters`）。
   Graph/Tableは同じselectorを使うため条件が共通になる。フィルター適用後に
   両端が可視でない辺は落とし、宙に浮く辺を作らない。
5. **状態**：`tableSort`・`tablePage`・`searchResults`・`temporaryDisplayIds` をViewStateへ
   追加。Graph/Table切替・再描画で選択・検索・フィルター・ソート・ページが消えない。

## 未検証事項

- 射影の外にある子ノードのホスト取得（スコープ単位の再問い合わせ）は未接続。ツリーは

- 検索のdebounce・検索索引の性能は未計測（SD-028）。

- VS Code Webview内での表示（fixtureページで確認）。

## 判断・補足

- ツリーの展開状態は永続化対象ではない（計画書7.5の保存項目に含まれない）ため、
  コンポーネント内の集合で管理する。選択・スコープは状態側にある。
- Tableの「行数上限」はページングに置き換えた。表示予算（射影）とは独立している。
- 一時表示はフィルターを書き換えない。フィルターの意味を変えずに「今だけ見せる」
  経路を用意し、解除できるようにした。
