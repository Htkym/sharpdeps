## 実装内容

1. **keyed更新とレイアウトの世代管理**：`graphView`は射影のキー（粒度・スコープ・ノード/辺ID）が
   変わったときだけELKへ要求する。選択・Inspector・検索語の変更では再レイアウトしない。
   複数のレイアウト要求は世代番号で古い結果を捨て、`dispose`でworkerを終了しBlob URLを解放する。
2. **選択とhit-area**：辺は透明の太い`path.edge-hit`で当たり判定し、クリック/Enter/ダブルクリックで
   選択・活性化する。集計辺のIDは**代表関係ID**（根拠が最多の関係、同数はID順）とし、
   `underlyingRelationIds`で下位の関係を保持する。これにより辺クリック→根拠ページングが成立する。
3. **循環・生成・推定の表示**：ノードは`inCycle`、辺は循環・`generatedEvidenceCount>0`
   （生成）・`basis==='usingInferred'`（推定、破線）をCSSクラスで区別する。推定のスタイルクラスが
   CSSの`.edge-inferred`と一致していなかったため写像を修正した。方向は矢印で示す。
4. **camera**：wheel（Ctrl/Meta）+ドラッグpan+Fit。射影が変わったときだけ内容サイズを設定してfitし、
   選択やInspector開閉ではcameraに触れない。フィルタ/検索の結果をそのまま描画するため、
   表示中のノードとサマリの数が食い違わない。
5. **失敗時の継続**：レイアウトが失敗してもエラーを表示し、Tableは常に同じ解析結果で描画済みなので
   解析結果そのものを失わない。worker URIが無い場合も同様にTableで継続する。
6. **パネル切替**：`codeMapPanel`は`validateWebviewMessage`→`reportBridge`で応答し、`ready`で
   capabilitiesと現在の解析状態を返す。`analyze`/`cancelAnalysis`は拡張側の処理へ委譲する。
   モードはWebviewの選択が優先され、Semanticは従来どおり明示的に非対応を通知する（黙って代替しない）。
   HTMLは新シェル（`media/app/entry.js`・`shell.css`・`graph.css`）とworker URI、strict CSPを配信する。

## 判断・補足

- 集計辺のIDを代表関係IDにしたのは、「辺クリックのIDが根拠と一致する」という受入条件を、
  二重の根拠ストアを作らずに満たすため。下位の関係は`underlyingRelationIds`で辿れる。
- v1ビューア（`media/viewer.ts`・`viewModel.ts`・`html.ts`の旧資産）は削除していない。循環診断は
  引き続きv1レポートを読むため、整理はSD-030で行う。
- Tableはグラフ表示中も常に描画しておく（切替時にグラフの成功に依存しないため）。
