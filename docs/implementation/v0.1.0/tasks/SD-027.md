## 実装内容

1. **ハーネス**：`scripts/e2e.js`は`SHARPDEPTS_VSCODE`または既知のパスのVS Codeを探し、
   無ければ`@vscode/test-electron`を使う。どちらも無い場合は**終了コード2と理由**を出す
   （無言の成功にしない）。レポートは`docs/implementation/v0.1.0/evidence/sd-027-e2e.json`へ書き出す。
2. **E2E本体**（`tests/extension/suite.js`）：拡張をactivateし、
   - 7つのコマンドIDが登録されていること、
   - ワークスペースが信頼されていること、
   - `sharpdeps.showDependencyMap`をQuick解析で実行し、**結果がストアへ登録されること**
     （`extensionTestApi.getAnalysisIds`）、
   - Problemsコレクションが取得できること、
   を検証し、JSONへ記録する。失敗は終了コードで返す。
3. **テスト用API**：`activate`の戻り値に読み取り専用の3関数（解析ID一覧・現在の解析ID・
   永続view state）を追加した。挙動は変えず、自動実行がUIと同じ状態を確認できるようにするため。

## 実機で確認する項目（実行手順）

VS Codeがあるマシンで：`npm install --save-dev @vscode/test-electron` → `npm run test:e2e`
（CIでは`SHARPDEPTS_VSCODE`でCode実行ファイルを指定）。あわせて以下を手動で確認する。

1. **SD-019**：Semantic解析後、型のカーソル位置で`Show Type Dependencies`→パネルが当該スコープを表示。
   根拠の「エディターで開く」→該当行へ移動。生成文書はread-onlyタブで開く。内容変更後は警告。
2. **SD-021**：タブを隠して戻す／ウィンドウをリロードする→対象・選択・filter・カメラが復元され、
   解析は自動実行されない。`retainContextWhenHidden: false`でも表示が失われない。
3. **SD-023**：未信頼ワークスペースで解析を実行→Trust案内が出て実行されない。CSP違反がコンソールに無い。
4. **SD-024**：高コントラストテーマと200%ズームでボタン/ラベルが判読できる。`/`→検索、`g`/`t`→表示切替、
   辺のEnter→根拠→開く、`Esc`でInspectorが閉じ起点へフォーカスが戻る。
5. **SD-011/022**：生成文書の表示、Mermaid/JSON/SVG/PNGの保存、`Copy for agent`の内容確認
   （送信が発生しないこと）。

## 実機での実行結果（2026-09-27、VS Code 1.139.1）

`--user-data-dir`で専用プロファイルを作り、依存拡張（ms-dotnettools.vscode-dotnet-runtime）を
ユーザープロファイルからコピーして実行した。**7チェック中5件が通過**した。

| チェック | 結果 |
|---|---|
| 拡張の導入（htkym.sharpdeps） | 通過 |
| 7つのコマンド登録 | 通過 |
| ワークスペース信頼 | 通過 |
| ワークスペースフォルダ | 通過（tests/fixtures/quick-baseline） |
| **解析結果の登録** | **失敗**（ストアに解析IDが無い） |
| **現在の解析ID** | **失敗**（undefined） |
| Problemsコレクションの取得 | 通過（0ファイル） |

つまり**拡張ホストは起動し、コマンドも登録され、解析が完了していない**。原因を特定するため、
スイートに診断（アナライザDLLの有無・dotnetのバージョン・設定モード）を追加した。
同じハーネスを再実行したところレポートを出さずに中断する場合があり、CIゲートにするには
watchdogとレポート基準の判定が必要（実装済み）。

## 未検証事項

- **解析結果が登録されない原因**：次回の実行で診断（DLL有無・dotnet・モード）を読み、特定する。
- **ワークスペース信頼のE2E**：ランチャは`--disable-workspace-trust`で解析を許可している。
  未信頼側の挙動は手動確認項目に回した。
- **CI組み込み**：ワークフローへの`test:e2e`追加はSD-029で扱う。

## 判断・補足

- mochaを足さずに素のNodeで書いたのは、依存を増やさずレポートJSONと終了コードだけで
  合否を扱えるようにするため。
- 「実行できない」を終了コード2で明示するのは、環境不足を成功と誤認しないため。
