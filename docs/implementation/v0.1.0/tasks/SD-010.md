## 実装内容

1. **body一走査**：メソッド本体・式本体・プロパティ/イベントのアクセサ・
   フィールド/イベントの初期化子・コンストラクター初期化子・トップレベル文・
   属性引数を「走査の起点」とし、その起点のOperation木を**一度だけ**辿る。
   ラムダとローカル関数は起点にせず、含むbodyから到達させる（同じbodyを子孫ごとに
   再走査しない）。
2. **種別の採取**：`constructs`（`new`/target-typed `new`）、`calls`（
   `IInvocationOperation.TargetMethod`。拡張メソッドは `ReducedFrom` の宣言型）、
   `memberAccess`（property/field/event。参照先メンバーを記録）、`typeUse`（`typeof`・
   明示キャスト・`is`型・`default(T)`・配列生成の要素型）、`compileTimeName`（`nameof`。
   ローカル名・引数名は型依存にしない）。
3. **仮想/インターフェース呼出し**：コンパイラーが束縛した宣言（インターフェースなら
   インターフェース）への辺とし、実行時の実装型は推測しない。
4. **帰属**：参照は包含型へ、メンバーは `SourceMemberId` へ記録する。アクセサは
   所属するプロパティ/イベントへ、ラムダ・ローカル関数は含むメンバーへ帰属させる。
   トップレベル文は合成エントリーポイント `Program`（とその `<Main>$`）へ帰属させ、
   namespace宣言がないことを理由に捨てない。
5. **未解決の区別**：`IInvalidOperation`・error型・`ContainingType` が得られない呼出しを
   未解決、dynamic型のレシーバー/リテラルを dynamic、`GetSymbolInfo` が候補のみを返す
   呼出し・メンバー参照を候補のみとして件数を記録し、根拠にはしない。
6. **重複排除**：根拠IDは `relationId + kind + documentId + 位置`。
   同じ `new` に対して `constructs` と `typeUse` を二重に作らない。

## 判断・補足

- 「起点ごとに一度だけ辿る」方式のため、`IOperation` の全Descendantを複数回走査しない。
  走査起点は宣言構文から機械的に列挙でき、テストでbody数を検証している。
- 属性引数の `typeof`/`nameof` はSD-010が採取し、SD-009は属性型のみを採取する
  （同じ構文を二重に数えない規則を `docs/analysis-semantics.md` に明記）。
- 合成エントリーポイントを含めるため、索引は「暗黙宣言の型は除外」から
  「トップレベル文の `Program` だけは含める」へ変更した。
