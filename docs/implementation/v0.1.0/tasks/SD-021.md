## 実装内容

1. **Staleの検知**：解析対象に含まれるファイルの**未保存編集**（`onDidChangeTextDocument`で
   `isDirty`）、**保存**（`onDidSaveTextDocument`）、**構成変更**（`sharpdeps`設定）で
   `stale`メッセージをパネルへ送る。対象判定はmanifestの相対パスで行い、無関係なファイルでは
   発火しない。自動更新は実装していない（既定OFFの要件を満たす。入れる場合のdebounce/集約も未実装）。
2. **状態の保存**：`getState/setState`（Webview）と`workspaceState`（ホスト）へ、対象名・選択・
   filter・スコープ・粒度・表示種別・検索語・ペイン幅・テーブル頁・カメラのみを保存する。
   保存は300msのdebounceで、状態変化時にまとめて行う。
3. **復元**：起動時に`getState`→`stateRestored`、`ready`後にホストの`viewState`→`stateRestored`。
   **解析状態は保存しない**ため、復元で解析は起動しない（`stateRestored`は`status==='analyzing'`を
   `ready`に落とす）。版が一致しないstateは推測せず捨てる。
4. **クラッシュ耐性**：ペイン幅は140〜480/200〜720へクランプし、ズームは0.2〜6へクランプ。
   不正なスコープ（idなしの局所スコープ）はrootへ、不正なfilter・表頁は捨てる。これらを
   単体テストで固定した。
5. **カメラ**：射影適用時に復元カメラがあればfitせずに適用し、pan/zoom後は状態へ反映して保存する。

## 未検証事項

- **タブを隠して戻す/リロードでの復元**：ブラウザfixtureで、永続化（localStorageへ302バイト保存）は
  確認できたが、リロード後の復元待ちがタイムアウトし、選択・検索・カメラの復元を最後まで
  確認できていない。このため**`retainContextWhenHidden`は`true`のまま**にした（計画の手順どおり、
  復元検証の完了後に切り替える）。次段でfixtureの起動順（`getState`復元とホストからの
  `viewState`の二重適用）を確認して完了させる。
- **再起動時の挙動**：workspaceStateからの復元は実装したがVS Code実機での確認は未実施（SD-027）。
  解析状態を保存していないため自動実行は起きない設計だが、実機で保証する。
- **自動更新**：実装していない（既定OFF）。入れる場合のdebounceと要求集約は未着手。
- **Problemsのstale表示**：`stale`メッセージのUI表示は既存（statusヘッダ）。実機確認はSD-027。

## 判断・補足

- 検証が完了していない`retainContextWhenHidden: false`への変更は行わなかった。復元が壊れていると
  タブ切替で表示を失うため、計画の「検証した後に変更する」に従った。
- 保存対象から解析結果そのものは除外した。復元でSemanticを自動起動しない要件を、
  保存データの形で保証するため（状態にanalysisIdを持たせない）。
