## 実装内容

1. **世代管理**：要求ごとに世代番号とrequestIdを**同期的に**確保する。連続して解析を
   押しても、古い実行が後から完了して新しい結果を上書きしない（`onCompleted`は
   最新世代のみに通知）。起動途中で新しい要求が来た実行は即座に停止する。
2. **進捗**：`sharpdeps:progress {...}` を解析して段階（discover/load/compile/extract/
   aggregate/write）と件数を通知する。分母が不明な段階に架空の%は出さない。
3. **ログ**：上限付きring buffer（既定500行）とOutputChannel。stdout/stderrを
   無制限に連結しない。
4. **timeout**：既定180秒（設定可能）。超過すると停止し、状態は `timeout` として
   キャンセルと区別して報告する。
5. **停止の順序**：協調停止（stdinを閉じる。POSIXではSIGTERMも）→猶予（既定3秒）→
   **自分が起動したプロセスツリーのみ**を強制終了（Windowsは `taskkill /T /F`、
   POSIXはデタッチしたプロセスグループへSIGKILL）。名前でプロセスを探してkillしない。
6. **cleanup**：作業ディレクトリは完了/失敗/キャンセルのいずれでも削除する。
   パネル終了・deactivate・異常終了も `dispose()` で同じ経路を通る。
7. **協調停止のホスト側**：`--watch-stdin` を渡したときだけstdinのEOFを停止要求として
   扱う（既定は無効。呼び出し元がstdinを閉じたまま実行するケースで誤停止しない）。
   キャンセル時は終了コード3で終了する。
8. **Extension配線**：`runAndShow` がコントローラーで実行し、完了時にReportStoreへ登録する。
   v1レポートは従来どおりパネルの描画に使い、v2は新しいUI（SD-015）用に保持する。

## 判断・補足

- 協調停止を `--watch-stdin` のオプトインにした理由：呼び出し元がstdinを閉じたまま
  （または即EOFで）起動するケースで誤って即キャンセルする事故を避けるため。
  拡張機能は自分でパイプを保持するのでオプトインする。
- 世代番号を非同期処理の前に確保する設計にした。`await` を挟むと2つの要求が
  同時に「自分が最新」と判断してしまう（実装中にテストで検出した不具合）。
- v1レポートは当面パネル描画に残す。v2ストアは登録済みで、SD-015のUIが使う。
