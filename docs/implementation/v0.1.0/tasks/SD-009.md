## 実装内容

1. **宣言由来の収集**：`inherits`（基底型）・`implements`（インターフェース）・
   `signature`（引数/戻り値/プロパティ/フィールド/イベント/インデクサ/演算子/recordの位置パラメーター）・
   `constraint`（ジェネリック制約）・`attribute`（属性型）を、宣言位置の根拠つきで採取する。
   ソースに書かれた型だけを対象とし、暗黙の `System.Object` 継承、recordが自動実装する
   `IEquatable<T>`、enumの基になる型は採取しない。
2. **正規化**：1つの書き方＝1件の根拠とした。型引数・tuple要素・配列/nullable/ポインタの
   要素型はそれぞれの構文位置を根拠にする。完全修飾名は展開しない（同じ参照を
   別スパンで二重計上しないため）。型パラメーター・`dynamic`・error型は解決できないので
   根拠を作らない。
3. **公開面**：`publicSurface` は包含型を含む実効アクセシビリティで判定する
   （メンバーと包含型のすべてが `public`/`protected`/`protected internal` のとき真）。
   `internal` 型の `public` メンバーは外部公開面にならない。
4. **集計への分類**：根拠に `SameNamespace` / `SameProjectVariant` / `TargetIsExternal` /
   `IsSelfReference` を付ける。SD-012はこれを使って、上位粒度の自己辺を作らず、
   型の自己参照を循環として扱わない。
5. **重複排除**：根拠IDは `relationId + kind + documentId + 位置` から作り、
   同じ場所の同じ種別は1件にまとめる。

## 未検証事項

- 関係と根拠の集計（`Relation` の生成・件数・witness）はSD-012で実装する。
- `constructs`/`calls`/`memberAccess`/`typeUse`/`compileTimeName` はSD-010で実装する。
- v2 `AnalysisSnapshot` への出力はSD-012/013。
- 名前空間・プロジェクト粒度での自己辺除外は、分類情報を付けた段階まで
  （実際の除外は集計側のSD-012で実装し、テストする）。
- 大規模ソリューションでの収集時間・メモリは未計測（SD-028）。

## 判断・補足

- 収集した根拠は `CollectedEvidence`（根拠＋分類）として返し、関係の生成は
  SD-012へ回した。件数の定義が1か所（`docs/analysis-semantics.md`）に留まる。
- 属性引数の中の `typeof` は属性型と合わせて二重計上しないよう、SD-010の `typeUse` に
  委ねる（規則を docs/analysis-semantics.md に明記）。
- `SymbolIndexBuilder.Build` に文書レジストリを受け取るオーバーロードを足し、
  索引と根拠収集が同じ文書IDを共有するようにした。
