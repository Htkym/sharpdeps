# 解析セマンティクス（件数と関係の定義）

v0.1.0の解析結果をどう数え、どう表示するかを固定する。SD-010/SD-012で確定する
重複排除規則をここへ追記していく。計画書5.3・6.4の実装上の正本とする。

## 指標の定義

| 指標 | 定義 |
|---|---|
| 関係数 | `source → target` の一意な組。`basis` と解析プロファイルが違えば別の関係 |
| 参照箇所数 | 正規化した `Evidence` の件数。同じ参照を構文とOperationで二重に数えない |
| 依存先数 | distinctな target ノード数 |
| 被依存元数 | distinctな source ノード数 |
| 根拠種別数 | 同じ辺に含まれる異なる `kind` の数 |
| 循環グループ数 | 非自明なSCCの数。閉路の総数ではない |

## 同じ参照を二重に数えない規則

`new Foo()` の型参照とコンストラクター呼び出しを2件として数えない。
同じ構文範囲が同じ対象を示す場合の優先順位を次に固定する（SD-010で実装・検証する）。

1. 構文ノードと `IOperation` が同じ対象を指す場合は `IOperation` の種別を優先する
   （例：object creation → `constructs`）。
2. 1つの式が型参照とメンバー参照の両方を示す場合は、実際に解決されたシンボルを
   優先する（`memberAccess` > `typeUse`）。
3. 型引数・配列要素型・tuple要素型・nullableの内側の型は別対象として残す。
4. `using` ディレクティブはSemanticの根拠にしない（`usingInferred` はQuick専用）。

### 宣言由来の参照（SD-009で実装）

宣言が明示的に書いている型だけを採取する。

- 採取する種別：`inherits`（基底型）・`implements`（インターフェース）・`signature`
  （引数/戻り値/プロパティ/フィールド/イベント/インデクサ/演算子/recordの位置パラメーター）・
  `constraint`（ジェネリック制約）・`attribute`（属性型）。
- **採取しないもの**：暗黙の `System.Object` 継承、コンパイラーが生成するインターフェース
  （recordの `IEquatable<T>` など）、enumの基になる型。宣言に書かれていない依存で
  グラフを埋めない。
- `typeof`・キャスト・パターン・ローカル型は SD-010 の `typeUse` が担当する（同じ構文を
  二重に数えないため、属性引数の中の `typeof` も SD-009 では採取しない）。

### 型参照の正規化

1つの書き方＝1件の根拠とする。

| 書き方 | 対象 | 備考 |
|---|---|---|
| `Foo` | `Foo`（定義） | 構築済みジェネリックは定義に正規化する |
| `Foo<Bar>` | `Foo`（定義）＋ `Bar` | 型引数はそれぞれの位置を根拠に持つ |
| `Foo[]` / `Foo*` | `Foo`（要素型） | 配列型そのものはノードにしない |
| `Foo?`（参照型） | `Foo` | nullable注釈は型を変えない |
| `int?` | `int` | `Nullable<T>` の内側を採る |
| `(Foo, Bar)` | `Foo` ＋ `Bar` | tuple要素をそれぞれ採る |
| 完全修飾名 `A.B.Foo` | `Foo`（定義） | 名前の各部分は展開しない（二重計上を避ける） |
| 型パラメーター `T` / `dynamic` / error型 | 採取しない | 確定したシンボルへ昇格させない |

### 自己参照と親の内部関係

- 同一型への参照（`class Node { public Node Next { get; set; } }`）は根拠として保持するが、
  循環判定の対象からは除外する（型の自己参照を依存循環として警告しない）。
- 集計時の分類として `SameNamespace` / `SameProjectVariant` を根拠へ付ける。
  名前空間へ集計するときは `SameNamespace` の関係を、プロジェクトへ集計するときは
  `SameProjectVariant` の関係を、その粒度の辺にしない（自己辺を作らない）。

### 実使用の参照（SD-010で実装）

実行されるコードから採取する。**1つのbodyにつき1回だけ**走査する（bodyのOperation木を
一度だけ辿り、同じbodyを子孫ごとに再走査しない）。

| 種別 | 採取元 | 対象 |
|---|---|---|
| `constructs` | `IObjectCreationOperation`（`new()`/`new T()`） | 生成される型 |
| `calls` | `IInvocationOperation.TargetMethod` | 宣言側の型（拡張メソッドは `ReducedFrom` の宣言型） |
| `memberAccess` | property/field/eventの参照 | メンバーの宣言側の型 |
| `typeUse` | `typeof`・明示キャスト・`is`型・`default(T)`・配列生成の要素型 | 対象型 |
| `compileTimeName` | `nameof(...)` | 参照したメンバーの宣言型（ローカル名・引数名は型依存にしない） |

- 仮想呼出し・インターフェース呼出しは**コンパイラーが束縛した宣言**への辺とする。
  実行時の実装型は推測しない。
- ラムダ・ローカル関数の中の参照は、それを含むメンバーへ帰属させる。
- トップレベル文は合成エントリーポイント（`Program`）へ帰属させ、捨てない。
- `new`で生成した型に対して同時に `typeUse` を作らない（1つの書き方＝1件）。

### 未解決・動的・候補のみ

確定したシンボルへ昇格させない。件数を記録し、制約として表示する。

| 分類 | 判定 | 扱い |
|---|---|---|
| 未解決 | `IInvalidOperation`、error型、`ContainingType` が得られない呼出し | 根拠を作らず件数を記録 |
| dynamic | dynamic型のレシーバー・リテラル | 根拠を作らず件数を記録 |
| 候補のみ | `GetSymbolInfo` が候補だけを返す呼出し・メンバー参照 | 根拠を作らず件数を記録 |
| 静的呼出し | `TargetMethod` が確定し、`ContainingType` が得られる | `calls` の根拠 |

### 参照種別の対応

- 属性引数の `typeof`/`nameof` は SD-010 が採取する（SD-009は属性型のみ）。
- 既定の引数値の式は今回採取しない（未対応として記録する）。
- ジェネリックの型引数は SD-009 の宣言参照として採取し、実使用側では
  型引数の利用（`new List<Order>()` の `Order`）ごとに1件の根拠とする。

### 公開面（publicSurface）

`publicSurface` は包含型を含めた実効アクセシビリティで判定する。メンバー自身と
それを含むすべての型が `public` / `protected` / `protected internal` のときに真とする。
`internal` 型の `public` メンバーや、`file` 型のメンバーは外部公開面ではない。

## 集計の規則

型→名前空間→プロジェクトへ集計するとき、同じ親の内部に収まる関係は
その上位グラフの辺にしない。型内部の自己呼び出しを「型の循環依存」として警告しない。

## 循環の規則

- 循環は解析済みの関係集合全体に対してSCCを計算する。描画範囲の切り出しより前に実行する。
- `basis`・解析プロファイル・粒度を混ぜたSCCを作らない。
- 代表閉路（witness）はSCC内部の実在有向辺をDFSで辿って得る。ノード名をソートして
  矢印で結んだものを経路として表示しない。
- 全閉路の列挙は行わない。

## 被依存探索の規則

- 逆隣接リストに対する幅優先探索で、直接と間接を区別する。初期深さ1、最大3。
- 打ち切りが発生した場合は件数を表示する。
- 結果は「確認候補」であり、障害影響やテスト十分性の保証ではないと表示する。

## プロファイルの規則

- Configurationの初期値は `Debug`。実際に使用した値を常時表示する。
- マルチTFMは整合した1つの解析プロファイル単位で表示し、TFMの異なる辺をunionしない。
- プロファイルを変更したら再解析が必要で、異なるプロファイルの根拠を再利用しない。
