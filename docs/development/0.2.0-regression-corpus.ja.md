# 0.2.0の観測corpus採用

J-02ではLithoSharpと同じ[regression-corpus-v1.json](regression-corpus-v1.json)を採用します。基準はSharpDeps `e16985d01c1e8e5f4bc1a530f84389ba308b1545`、LithoSharp `9317af45a7bf8b08b000b693d27fbe33406db7a6`です。source path、symbol/test title、Git blob ID、blob bytesのSHA256、fixture tree IDを索引に固定します。設計文書と既存goldenの照合で、新harnessの実行結果ではありません。

共通の選定理由、旧oracle境界、差の記録方法はLithoSharpの `docs/development/2.0.0-regression-corpus.ja.md` を参照します。両repoで索引を変更するときは同一bytesに揃え、理由をレビューします。

## SharpDepsの観測と担当境界

| ID | 採用する基準 | 保持する観測 | 変更時に使うタスク |
| --- | --- | --- | --- |
| C02 | J-01 fixture、既存inspectionの区別 | raw UTF-16/segments、Partialを完全扱いしない、Scope/Source/SourceVersionとhashのbinding | SD2-03、IN-01。DTOはMD-02、host/cacheはMD-04 |
| C05 | quick-baselineとbuildStructureSnapshot | partial/inferred、types=0、relations=15、evidence=17、coverageと限定事項、証拠位置 | SD2-01、SD2-02、SD2-08、IN-01 |
| C06 | semantic-baselineとsummarize | completeWithinScope、Domainの2 TFM、generated source、symbolResolved=46/projectEvaluated=3、confidence resolved=49 | SD2-01、SD2-02、SD2-08、IN-01 |
| C07 | 既存IOperation/位置の小さいcanary | unused usingでedgeを増やさない、candidate/dynamic/unresolvedをresolvedへ昇格しない、mapped/physical位置を区別 | SD2-01、SD2-02、IN-03 |

C05/C06の数は固定fixtureの旧goldenです。新member graphの追加で旧report v2/providerの意味を変更しません。確認できた欠落を修正する場合だけ、input/symbol/before/afterの根拠をレビューしてgoldenを更新します。新規member根拠やdocument graphの期待値は担当taskで追加し、現行で生成済みとは扱いません。

root固有ID・時刻・絶対パスの正規化には既存helperを使います。TFM/variant分離、confidence、mapped/physical span、generated/sourceの区別は残します。同じroot/checkoutのID安定性も維持します。unused usingで行が移る場合はkind/source/targetの集合を比較し、位置由来IDの全一致は要求しません。

C07のmapped位置は、filename付き#line120ではstartLine119/physical startLine2、filenameなし#line70ではstartLine69/physical startLine2です。コード利用のないProjectReferenceはprojectEvaluated根拠を保持し、physicalSpanはnullです。IOperation collectorは候補だけの参照をemitせず、dynamic/unresolvedを確定edgeとして生成しません。

## 小さい確認と差の記録

J-02では既存Quick/Semantic goldenを読み戻し、索引のprojectionと照合します。既存のtest/normalizerを複製した新test frameworkやraw巨大snapshotは作りません。後続taskで実装を変更したら、触れた境界に対応する既存caseを選んで実行し、失敗や未解決の境界がある場合だけ確認範囲を広げます。

task証拠にcase ID、input ref/hash、基準/候補SHA、実行commandと結果、差の理由、未実行理由を残します。golden更新flagだけで差を消しません。新Query/storage/watchやAnalyzer hostの検証は担当taskで小さく追加します。現在のcorpusの既存CI成功を、それらの実装確認へ流用しません。

Markdigの参照比較は既存のLithoSharp側test projectに隔離され、ロックresolved版は1.4.0です。SharpDepsや公開packageにoracle依存を追加しません。AngleSharpは現行LithoSharp製品依存に残っており、J-02で撤去したとは記録しません。新共有Markdownのstrict入力や位置契約は後続で同版runtime/source hostから実確認します。

## CI証拠と停止条件

基準SHAに対する[run 37715916248](https://github.com/Htkym/sharpdeps/actions/runs/37715916248)はbuild/macOS smokeと既存Quick/Semantic golden検証が成功しています。以前のrun 37709418593ではfixture restoreが失敗しましたが、原因は未確定です。成功したJ-01のexact SHAを今回の基準とし、旧失敗の原因調査をJ-02の追加条件にしません。

同PCのZendiator計測を優先し、ローカルbuild/test/restore/packは実行しません。JSON読戻し、両repoの索引同一性、source/golden/hash/task対応、git diff checkだけを今回の軽い確認にします。J-02のfeature commit/push後はBocchiのdiffレビューを待ち、次taskやharness実装へ進みません。
