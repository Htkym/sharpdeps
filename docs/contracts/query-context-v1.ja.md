# SharpDeps Query/context契約 v1

`SharpDeps.Query`はsearch、symbol、callers、callees、impact、context、statusを提供する。`QueryService.Execute(QueryRequest)`が個別Queryの共通入口であり、CLI、保存QueryHost、MCPのtyped `explore`が同じ保存graphを使う。旧report v2とは別の契約で、現在のSQLite schemaと再索引条件は[保存契約](index-storage-v1.ja.md)、各hostの入口は[CLI](cli-skill-v1.ja.md)と[MCP](mcp-stdio-v1.ja.md)を参照する。

`PinnedQueryIndex`は呼出し側が所有する一つの`IndexReader`を使う。graphとFTSは同じcommitted世代に固定される。呼出し側はQueryを終えた後にreaderをdisposeする。QueryServiceはthread-safeではなく、保存graphとrequestの配列を複製・検証して使う。QueryService自体にwriter、解析器、restore、network、processの入口はない。

`IndexReader.Snapshot`は全体の検証後に入れ子のcollectionまでread-onlyに固定したsnapshotを返す。`IReadOnlyList`を`IList`等へcastして変更すると`NotSupportedException`になる。変更には必要なcollectionを複製した新しいsnapshotを作り、明示更新を使う。exploreは`PinnedQueryIndex`の同じreader内で準備済みデータを再利用し、全量の再JSON化・clone・再検証を行わない。任意の`IQueryIndex`から受け取るpayloadは従来どおり複製・検証する。内容検証、世代固定、readerの寿命、requestごとのsource／鮮度検証は維持する。

## 検索、詳細と探索

Searchはexact ID、name/signature、path、FTS、literal substringの順に候補を選び、同順位はordinal IDで整列する。kind/project/path/variantのscopeを同じ保存graphへ適用する。partial symbolでは選択variantの宣言位置もpathの根拠にし、Symbolの返却宣言もpathをfilterする。曖昧な短名を一つのsymbolへ自動確定しない。Symbolはexact IDとvariant別occurrence/宣言を返す。

既存FTS primitiveは500hit上限を持つ。scope適合する保存SearchText/名前/signature/pathのliteral候補は全graphを走査して補う。FTSが500hitに到達した場合、または正しい順位の候補を500件より先に保持できない場合は`SEARCH_CANDIDATE_LIMIT`を付け、網羅性を主張しない。totalは未走査の全件数として返さない。

Callers/Calleesの既定edge kindはcalls、constructs、dispatch_candidates、candidate_relationで、方向はincoming/outgoingである。ImpactはID群またはTermのfile/path検索を起点とし、方向、edge kind、depth、includeDocumentsを指定できる。各itemは経路のedge IDsとreasonを持つ。Impactは確認すべき候補であり、変更必須や候補外の安全性を証明しない。

Resolved、Candidate、Unresolvedはそれぞれ`items`、`candidates`、`unresolved`の別配列へ出す。候補は既定の厳密探索に含めない。includeCandidatesで出す候補はleafとして止め、候補を経た先のResolved辺を起点から確定した関連へ強めない。静的束縛はruntime dispatchの確定ではない。

探索はordinal edge順のBFSで、logical node ID、到達occurrence ID、variantの組をvisitedに保持して循環を止める。outgoingでは到達target occurrenceと次辺のsource occurrence、incomingでは到達source occurrenceと次辺のtarget occurrenceを一致させる。cross-project辺は明示された接続先occurrenceの実variantへ遷移する。occurrenceがnullの端点からlogical IDだけで特定のoccurrenceを推測しない。既知occurrenceに対するvariant未指定のlogical-only文書関係は直接のleafとして返し、その先へ推測接続しない。文書などoccurrenceを持たない区間でも選択variantを保持し、別variantの辺を橋渡ししない。Contextの宣言と到達nodeの位置は実際に到達したoccurrenceから構成し、深さ打切りも同じ接続条件で判定する。同source/hashのsnippet範囲は整列して全交差範囲をunionし、一つの本文だけを返す。unknown spanはnullのまま扱う。source原文はDTOの元UTF-16、zero-based半開区間で、BOM/CRLFを除去しない。

## 世代、鮮度とtrust

`scope.resultKinds`はCode/Docs/Otherの返却分類、`scope.includeExternal=false`はExternalSymbolの除外を指定する。Document、Section、FrontMatter、CodeFence、LinkTarget、SymbolMentionはDocsである。SourceFileは保存manifestのkindからcode/source/generatedSource/packageSourceをCode、markdownをDocs、それ以外をOtherへ分類する。Project、Namespace、Type、Member、ExternalSymbolはCode、WorkspaceはOtherであり、文書kindの補集合をCodeとは扱わない。

Search/Browseでは分類をページング前に適用する。探索では非表示の文書構造を経由でき、返却時にnode/occurrenceを絞る。返却edgeは両端が表示条件に合う場合だけ残し、非表示区間を短絡する辺は作らない。探索予算、候補leaf、variant/occurrence接続条件は従来どおりで、非表示nodeを含む探索の打切りも記録する。分類集合は重複除去・整列してcursorへ結び付ける。応答のnode/occurrenceにはresultKind、snapshotにはresultFilterVersion=1を付ける。この機能は同markerを持つQueryHostでのみ利用でき、index schemaやsource読取り権限を変更しない。

全応答はapiVersion、requestId、workspace/snapshot/generation/variant/coverage、freshness、budget、truncated/reasons、nextCursor、diagnostics、errorsを持つ。Partial/FailedをCompleteへ補完しない。空結果、coverage不足、打切りを区別する。requireCompleteはcoverage不足やtruncationで`INCOMPLETE_RESULT`となり、QueryReply.Succeededはfalseになる。CLIのexit番号は[CLI契約](cli-skill-v1.ja.md#jsonと終了コード)に従う。

現行snapshotは`namespaceBrowseVersion=1`と`symbolDeclarationRowsVersion=1`を返す。Browseの`scope.parentId`は選択project内のNamespace直下のTypeを対象とし、Symbolの`includeDeclarationRows=true`はoccurrenceの宣言を一行ずつ返す。後者はSymbol以外で拒否し、各行の位置・occurrence・variantと件数／出力予算を維持する。宣言行のResolvedは宣言の存在を表し、文書からsymbolへのCandidate関係を確定しない。providerは対応markerを確認してから使う。

Cursorはworkspace、snapshot IDのSHA、generation、operation/filter/scope/variant/budget/freshnessと位置へ結び付け、HMACで検査する。process内の既定keyは再起動で変わる。hostは32byteのcursorKeyを明示供給できる。cursorは認証credentialではなく、opaque paging tokenである。別世代は`CURSOR_SNAPSHOT_EXPIRED`、別filterは`CURSOR_FILTER_CHANGED`、改変は`INVALID_CURSOR`を返して再検索を促す。同じreaderを続けて使う場合はその旧世代を表示し、新readerへ黙って接ぎ替えない。

ReadSavedはsource読取を含めない。既定isTrusted=falseのQueryServiceは渡されたworkspaceを保持せず、snippetとhash検査を行わない。allowStaleの未検査状態はunverifiedであり、currentと称しない。sourceアクセスは別のtrusted境界として`QueryWorkspace`を渡す。

QueryWorkspace.Readはmanifestの相対pathだけをroot内へ解決し、UNC、root外、symlink/junction/reparseを拒否する。一回のbounded読取bytesをSHA256、byte長、strict UTF-8/UTF-16長と照合した後、その同じbufferからsnippetを切る。不一致はsnippetを省略し`SOURCE_CHANGED_SINCE_SNAPSHOT`とdirty path/更新方法を返す。UTF-16 surrogateの途中を切らない。リンクを含むrootはcanonicalな実体pathをownerが渡す。Unixの敵対的link交換競合をnative handleで完全に防ぐ実装ではない。

requireFreshは全保存入力のraw hash、tombstone、現在の入力集合、現在設定の証明を検査し、選択/snippetの後にも再検査する。mtime/sizeの一致だけでは成功しない。trusted ownerが`QueryInputInventory`へ完全な選択集合とConfigurationVerifiedを渡す。これは同じ保存設定/variant/参照/SDK等と現在値を比較した証明であり、保存boolやcheap checkを転送する入口ではない。CLIは明示更新済みlive ownerの同世代closed-input proofを再照合するcallbackを接続する。callback未接続、集合不足、設定証明なし、読取不能はunverified/条件未達、既知変更はdirtyとなる。owner不在・再起動後の証明なし・別世代・更新中は拒否し、Queryからownerを起動しない。未知の入力閉包や任意workspace全体のfreshnessを証明できるとは主張しない。

refreshは`UPDATE_REQUIRED`を返す。trusted coordinatorで更新し、新しいreaderから再queryする。source検査はファイル集合全体の原子的snapshotではなく、checkedAt時点の検査である。検査後の外部編集を防ぐ保証はない。

## 出力と実行予算

今回の実装defaultは60nodes、120edges、depth2、1000ms、18000 UTF-16 JSON文字、64000 UTF-8 bytes、pageSize100である。設定範囲はnodes1–500、edges1–1000、depth1–8、time10–30000msまたは0、chars2048–1000000、bytes2048–4000000、pageSize1–500。`QueryBudget.MaxMilliseconds = 0`は計算期限を外す明示指定で、呼出し側の取消とその他の予算・検証は維持する。既定値と正の時間枠の意味は変わらない。宣言itemもnode枠へ数える。snippet本文は文字枠の半分まで先に割り当て、最終JSONでさらに制限する。

JSON escape、envelope、coverage/診断、error、cursor、使用量fieldを含む実serialized応答を計測し、自己サイズを安定化してから上限を検査する。必要ならpage末尾を減らし、optional metadataを省略してcountと打切り理由を残す。最小error envelopeが実snapshotの必須metadataを含めて収まらない予算はArgumentExceptionで事前拒否する。不正引数もArgumentExceptionで、hostが共通protocol errorへ変換する責務を持つ。本文の途中切断で壊れたJSONを返さない。

usedCharsは最終JSONのUTF-16長、usedBytesはそのUTF-8長である。estimatedTokensは文字数からの推定で、tokenizerの厳密な制限ではない。取消と時間枠は探索、source読取境界、最終wire構築で検査し、CANCELLED/QUERY_TIMEOUTを返す。同期SQLite/serializer/filesystem呼出そのものを強制中断するOS sandboxではない。

## Exploreの根拠とprovenance

現行の`explore`は名前・exact ID・source pathを入口に、scope内の保存済み実装と参照根拠をまとめる。曖昧なproject／variantを自動統合せず、明示scopeと`unique`／`prefer-debug`の選択に従う。`http-get-literal`は保存されたHttpGet宣言断片との完全一致であり、実効URLの解決ではない。`pathTo`はexact occurrence間の保存済みcall witnessを扱い、runtime到達性を証明しない。候補、omission、freshness、coverageを保つ。

通常ファイルは現在bytesと保存hashを照合してsnippetを切る。保存済み生成本文は実ファイル位置と区別し、保存snapshot由来のprovenanceを返す。パッケージ本文は明示的な検証を通した保存入力に限定する。生成本文やパッケージ本文を含む索引にはclosed-input reuse proofを発行せず、現在入力と一致する鮮度を推測しない。ReadSaved自体はsource本文を読まず、trustedなsourceアクセスの境界と件数・時間・出力予算を維持する。詳しい返却形式は[Exploreの案内](../mcp.md)を参照する。
