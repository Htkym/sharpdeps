# Full extraction oracle

The CLI test assembly also runs as a bounded extraction process:

    dotnet SharpDeps.Cli.Tests.dll --full-oracle request.json result.json

`OracleRun` supplies the exact CLI options, previous snapshot and search terms. Set `AllowSemanticReuse` to `false` for the reference extraction and `true` for the update. Both runs must use the same final workspace, workspace UUID, settings and previous snapshot, including document/section lineage. Use separate index paths under `.sharpdeps` and keep request/result files outside the workspace input inventory.

The integration test restores a small offline three-project fixture, then compares no-change, Markdown/document/section additions, a C# edit with a compiler error, source membership changes, and a project configuration change. It requires the closed-input profile and asserts actual semantic/collector reuse and full extraction counts on every verification host. The test output records proof admission and each step's extraction/reuse counters. It also checks the conservative full fallback on the first C# edit after a Markdown update, and on a project configuration change; those runs are not counted as reuse successes. It selects an installed .NET 10 SDK for restore with a temporary `global.json`, removes that file before capture, and asserts the actual extraction proof uses the same SDK. The offline restore configuration and explicit absolute NuGet package root remain outside the final workspace. The package-free restore and extraction children use that same root, avoiding host-default NuGet props containing unsupported property expressions. This changes only the test child environment; production proof admission is unchanged. Run with the existing `ProjectIncrementalTests` and `ParserFullOracleTests` using a fully-qualified-name filter.

The comparison includes every saved graph/index field, reuse evidence, IDs, certainty, source hashes/spans, legacy references, diagnostics, coverage, search text, and ordered FTS/Query results with exact ranks. Only `files[].reuse.projects.structureHash` (cache execution proof), graph snapshot ID/generation, Query snapshot ID/generation/checked time, the process ID, and Query wire usage (`usedChars`, `usedBytes`, `estimatedTokens`) are normalized. Wire usage depends on the excluded execution diagnostics; node/edge usage and budget limits remain compared. Execution diagnostics are separated by the explicit allowlist in `FullBuildOracle`: semantic reuse/loaded counts, collector counts, and per-project counters with a valid stable variant ID. Query copies of the saved execution diagnostics are removed only when they exactly match the known saved-diagnostic suffix, including long per-variant codes displayed as `GRAPH_DIAGNOSTIC`. Unknown diagnostics remain semantic comparison input. The semantic reuse path retains the previous project structure proof when Markdown changes, whereas full extraction refreshes it. This single hash is separated, its original values stay in the raw artifacts, and the resulting conservative fallback is asserted independently. All catalog and collector proof payloads remain compared. There is no wildcard metrics exclusion. If metrics are added to the serialized result, define their separation explicitly and assert the corresponding execution paths.

Snapshot UUIDs and new Markdown UUIDs/section tokens are deterministic only through the internal scoped test allocator. This also gives both paths the same snapshot-bound transient Markdown IDs. Default production allocation and all existing entry points remain unchanged. Failed-run request/result files and SQLite indexes are retained under the printed scratch root for reproduction. The host drains both redirected streams and kills its process tree on cancellation. The post-exit drain has a two-second limit. Timeout or cancellation cancels the underlying reads, closes both pipe readers and gives read cleanup at most one more second; eventual read failures are observed. Kill-after-cancellation exit cleanup is separately bounded to three seconds. A regression exits the parent while an owned descendant keeps both pipes open, verifies a drain timeout without caller cancellation, and reclaims that descendant in the test finally. The test-only descendant also has a 30-second fail-safe. This is not a general orphan-process reaper after a parent has already exited.

C# parser checks compare `WithChangedText` after bounded edits with a separate full parse, including text, node/token/trivia spans, missing/skipped tokens, directives and syntax diagnostics. Markdown checks compare prepared `ParseWithSyntax` facts with independent canonical full `Parse`, including nonpublic UTF-16 mapping state, diagnostics, coverage and TextHash. These parser API conformance checks do not by themselves establish retained semantic-session or Markdown parser-session reuse or performance. See the current [semantic-session](../../../docs/development/semantic-session.md) and [Markdown-preparation](../../../docs/development/markdown-session-cache.md) implementation notes for the separately bounded paths.

The Index stores aggregate compiler/loader diagnostics, not their full detailed reports. Equality therefore covers saved aggregates and semantic graph diagnostics, not unpublished compiler diagnostic details. The fixture is not a corpus comparison. Production corpus comparison remains a release gate for each later reuse/storage optimization.
