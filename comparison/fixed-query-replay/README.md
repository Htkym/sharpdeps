# Fixed-query process replay

Build the existing MCP test project, then run its test assembly as a replay harness:

```text
dotnet analyzer/tests/SharpDeps.Mcp.Tests/bin/Release/net10.0/SharpDeps.Mcp.Tests.dll --fixed-query-replay input.json new-receipt-directory
```

The input is a JSON object with `root`, `cliDll`, `mcpDll`, `repositoryRoot`, `trusted`, optional `index` (default `.sharpdeps/index.sqlite`), optional `phaseMetrics` (default `false`), and `cases`. Each case has `id`, `query`, explicit `format`, `freshness`, `maxChars`, `maxBytes`, `maxMilliseconds`, and optional `scopePolicy`, `projectId`, `variantId`, `pathPrefix`, `ownerStatus`, and `purpose`. Use absolute existing host/repository/workspace paths and a new output directory. The harness only queries an existing index; it does not restore, index, update, install or call a model.

`historical-cases.json` preserves five recovered queries and their explicit `unique` budgets. Each has a separately labelled omitted-policy discovery case. Set the appropriate fixed workspace for each corpus before use; do not execute EF Core and Orleans queries against an unrelated index. These are current-build replays of recovered requests, not exact historical-product reproductions: the original binary and index were not contemporaneously bound. The old instructions forcing `unique` must not silently replace the separate default-discovery condition.

Receipts retain the CLI argument vector, exact stdout/stderr bytes and exit status; MCP initialize, initialized notification, tools/schema, full request and raw JSON-RPC response; snapshot/source manifest and payload hashes; observed outcome, errors, omissions, scope and source units; raw source and exactly numbered/displayed source UTF-16/UTF-8 sizes, actual escaped tool-result JSON sizes and JSON-RPC envelope/line-delimiter overhead; and process wall/CPU observations. A final manifest hashes every retained artifact. Explore source is never added to protocol stdout or duplicated in `structuredContent`.

Audit source IDs and content hashes must match the snapshot. Raw spans are checked against hash-verified source bytes and the selected symbol's whole saved declaration boundaries, including merged complete ranges. Code scopes and saved document-to-code scope links are verified separately; a document-only response can legitimately have no code scope, an independent scope-policy decision, or a saved project with no selected variant. Agent responses are checked against saved declarations and retain possible spans when the display cannot prove a unique raw span. Physical source bytes preserve BOMs and their UTF-16 coordinates. Stored generated/package bytes come from the snapshot, without resolving virtual paths on disk. Receipts contain source code, so keep them in an authorized private destination.

The default equivalence rule requires identical CLI/MCP text and matching error status. `protocol-error` permits the documented CLI argument envelope versus MCP InvalidParams difference. `deadline-sensitive` retains independent cold-process deadline outcomes without asserting equal timings. These exceptions are explicit inputs, not exclusions chosen after observing a result.

Run the focused tests through the existing .NET test entrypoint:

```text
dotnet test analyzer/tests/SharpDeps.Mcp.Tests/SharpDeps.Mcp.Tests.csproj --filter FullyQualifiedName~FixedQueryReplayTests
```

Set `SHARPDEPS_REPLAY_SDK_HOME` to a directory containing the intended SDK `global.json` when SDK identity must be pinned. Set `SHARPDEPS_REPLAY_ARTIFACT_ROOT` to retain the test receipts at a chosen private directory. The tests cover exact members and overloads without unrelated neighbours, type/member fallback, partial declarations, three projects and four separate TFM/configuration scopes sharing a linked physical file, four encodings, Japanese/emoji/CRLF, stored generated/package inputs, escaped/tight/large wire budgets, explicit unique versus default discovery, no match, unsupported selection, trust, changed source, missing owner/configuration freshness proof, cold deadlines, generation boundaries and actual MCP cancellation-race observations. A sent cancellation notification is not proof that the host accepted cancellation. Process exit, stream drain and cancellation cleanup are bounded; a capture failure retains the artifacts already written. Negative oracle tests reject incorrect source provenance and unrelated complete declarations. Separate stdout/stderr overflow probes verify immediate read-failure cleanup while waiting for exit, finishing a session, or awaiting a protocol line.

Set `phaseMetrics: true` only for hosts supporting `--metrics-directory`. The default sends no diagnostic flags, preserving older-host replay. CLI cases use separate fresh sinks below the workspace's `.sharpdeps`; the sequential MCP host uses one fresh sink with before/after request boundaries. The host alone selects the sink, never tool arguments. Existing SDK/tool/package isolation guards still apply. A refused sink or missing file cannot distinguish pre-admission rejection from unavailable diagnostics unless the public response proves argument rejection.

Each receipt records separate CLI/MCP `phaseMilliseconds` and `phaseMetrics`, with exact JSONL copies and hashes per case. Values are the interval union of the named closed spans listed in `phaseMetrics.groups`, not sums of nested/repeated inclusive times or exclusive time. Groups may overlap and must not be added. Reader preparation covers reader open/snapshot and exploration preparation/derived indexes. Search/scope covers search, resolve, expand and discovery scope ranking/selection, excluding remaining discovery orchestration. Source verification covers source read/decode/hash/freshness, not unit selection. Rendering covers `explore.render`, not transport serialization. Failed/cancelled elapsed spans are retained without implying successful work. Unreached stages are null with reasons. Disabled, rejected, absent, malformed, truncated, unfinished, ambiguous or changed/out-of-boundary evidence remains explicitly unavailable. The collector bounds each sink to 4096 files/16 MiB and parsing to 64 KiB per JSONL record/65536 records, and verifies run IDs, contiguous sequence, schema, span identity, finite intervals and parent containment. A capture interruption retains available sidecars and a separate phase receipt before propagating the failure.

Limits: this is correctness/observability coverage, not a benchmark. Unreported candidate counts remain null. MCP request CPU is the host process delta; CLI CPU includes startup and the entire process. CLI OS-signal cancellation, a live coordinator's changed-configuration proof, concurrent publication during a request, packaged binaries, historical corpus execution and natural model usage require their separate acceptance runs. Do not infer tokens, costs or Read replacement from output sizes. Existing Query and MCP lifecycle tests retain their deeper semantic and mutation coverage.
